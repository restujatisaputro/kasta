# Katalog Test Case KASTA

Dokumen ini adalah katalog eksekusi (bukan bukti bahwa semua kasus sudah dijalankan). Kolom
**hasil aktual**, **status**, **catatan**, **penguji**, dan **tanggal** wajib diisi dari build dan
lingkungan yang benar. Salin baris yang akan dijalankan ke
[`actual-result-template.md`](actual-result-template.md) agar bukti lengkap dan dapat diaudit.

`Severity` menyatakan dampak apabila perilaku gagal; `Priority` menyatakan urutan eksekusi. P0/P1
harus lulus untuk kandidat rilis. Data uji selalu sintetis dan setiap kasus lintas tenant memakai
sedikitnya Usaha A dan Usaha B.

## Aturan eksekusi

1. Isi kolom Actual/Status/Catatan/Penguji/Tanggal hanya setelah test dijalankan; `NOT RUN` bukan
   status lulus.
2. Setiap FAIL wajib memiliki defect ID, request/correlation ID, dan artifact tersensor.
3. Kasus P0/P1 dijalankan pada setiap pull request atau release candidate sesuai test plan.
4. Kasus database/RLS dan backup harus dijalankan pada PostgreSQL/MinIO nyata; SQLite tidak dapat
   menggantikan pengujian RLS.
5. Setelah patch, jalankan retest kasus gagal dan regresi suite terdampak sebelum menutup defect.
